建置 blob 並 upload

1. az login

互動式登入；瀏覽器會開啟並要求 MFA

MFA：登入時，不只靠「密碼」，還要再用另一種方式證明你是本人。

CLI
az login

2. az group create

建立一個空的 lab resource group。這會改變目前 az-104 subscription，但 resource group 本身不計費；eastasia 只保存 resource group 的中繼資料位置，不限制未來資源必須部署在同一區域。

CLI
LAB_RG="rg-az104-foundation-lab"
LAB_LOCATION="eastasia"

az group create \
  --subscription "az-104" \
  --name "$LAB_RG" \
  --location "$LAB_LOCATION" \
  --tags purpose=az104-learning environment=lab \
  --query "{Name:name, Location:location, State:properties.provisioningState, Tags:tags}" \
  --output yaml

3. 建立 resource group 層級的 CanNotDelete lock

影響範圍是整個 rg-az104-foundation-lab；不產生成本、允許修改，但阻止刪除，且會向下套用到之後建立的資源。

Lock意思
CanNotDelete可以修改，但不能刪除
ReadOnly只能讀取，不能修改，也不能刪除

管理鎖適用於控制平面，不會直接阻止 Blob 等資料平面的讀寫或刪除。官方說明

CLI
LAB_RG="rg-az104-foundation-lab"
LOCK_NAME="lock-cannot-delete"

az group lock create \
  --subscription "az-104" \
  --resource-group "$LAB_RG" \
  --name "$LOCK_NAME" \
  --lock-type CanNotDelete \
  --notes "AZ-104 governance lab; remove before cleanup" \
  --query "{Name:name, Level:level, Notes:notes}" \
  --output yaml

4. 建立低成本的 Standard LRS StorageV2 account

它會繼承 resource group 的 CanNotDelete lock。計費依容量、交易及傳輸量計算；目前不放資料，成本通常極低，但不是保證零成本。

Storage Account 是 Azure 儲存服務的最外層資源，建立後依需求使用下列服務。

Storage Account
├─ Blob Storage   ≈ AWS S3
├─ Azure Files
├─ Queue Storage
└─ Table Storage

先向 azure 註冊資源, 需等候一段時間

CLI
az provider register \
  --subscription "az-104" \
  --namespace Microsoft.Storage \
  --wait

建立 storage

CLI
az storage account create \
  --subscription "az-104" \
  --resource-group "$LAB_RG" \
  --name "$STORAGE_ACCOUNT" \
  --location "$LAB_LOCATION" \
  --kind StorageV2 \
  --sku Standard_LRS \
  --access-tier Hot \
  --https-only true \
  --min-tls-version TLS1_2 \
  --allow-blob-public-access false \
  --allow-shared-key-access true \
  --public-network-access Enabled \
  --tags purpose=az104-learning environment=lab \
  --output none

5. 用 Microsoft Entra ID 存取 Blob，先替自己加入 Storage 資料角色，再建立私人 container。

  1. 建立角色指派：az role assignment create，指定 scope（此例為 Storage Account）。
  2. 建立容器：az storage container create。
CLI
LAB_RG="rg-az104-foundation-lab"
STORAGE_ACCOUNT="staz104lab002d36"   # 若名稱不同請修改
CONTAINER_NAME="private-lab"

ACCOUNT_ID=$(az storage account show \
  --subscription "az-104" \
  --resource-group "$LAB_RG" \
  --name "$STORAGE_ACCOUNT" \
  --query id \
  --output tsv)

USER_ID=$(az ad signed-in-user show \
  --query id \
  --output tsv)

建立 role

CLI
az role assignment create \
  --assignee-object-id "$USER_ID" \
  --assignee-principal-type User \
  --role "Storage Blob Data Contributor" \
  --scope "$ACCOUNT_ID" \
  --output table

建立 container

CLI
az storage container create \
  --account-name "staz104lab002d36" \
  --name "private-lab" \
  --auth-mode login \
  --public-access off \
  --output table

7. User Delegation SAS

Blob container 設為 private，因此不帶授權資訊的匿名請求無法讀取 Blob。 登入的 Entra 使用者可以產生短效、唯讀、僅限 HTTPS 的 User Delegation SAS。

SAS：有期限、有限權限的臨時存取憑證。拿到這個連結的人，可以在 SAS 規定的範圍內存取。

CLI
BLOB_URL="https://staz104lab002d36.blob.core.windows.net/private-lab/az104-blob-lab.txt"

curl --silent --show-error "$BLOB_URL"

EXPIRY=$(date -u -v+15M '+%Y-%m-%dT%H:%MZ')

SAS_URL=$(az storage blob generate-sas \
  --account-name "staz104lab002d36" \
  --container-name "private-lab" \
  --name "az104-blob-lab.txt" \
  --permissions r \
  --expiry "$EXPIRY" \
  --https-only \
  --auth-mode login \
  --as-user \
  --full-uri \
  --output tsv)

curl --fail \
  --silent \
  --show-error \
  "$SAS_URL"

unset SAS_URL EXPIRY

8. Blob Lifecycle Management

層級／動作儲存成本讀取成本
Hot高低
↓ Cool↓↑
↓ Cold↓↑
↓ Archive低高
↓ Delete0*—

成本為相對趨勢；Archive 需先解除封存才能讀取。Delete 是刪除動作；0 指資料完全移除後的儲存成本，軟刪除保留資料、版本或快照仍可能計費，也可能產生提前刪除費用。箭頭為概念順序，實際轉層與刪除依 Lifecycle 規則設定。官方說明

CLI
az storage account management-policy show \
  --subscription "az-104" \
  --resource-group "rg-az104-foundation-lab" \
  --account-name "staz104lab002d36" \
  --query "policy.rules[].{
    Name:name,
    Enabled:enabled,
    Actions:definition.actions,
    Filters:definition.filters
  }" \
  --output yaml

11. 建立 Azure Files 的 SMB file share

SMB：透過網路共享檔案／資料夾。

Azure Files
   │
   │ 使用 SMB 協定
   ↓
File Share
   │
   ├─ VM A
   ├─ VM B
   └─ App C
CLI
az storage share-rm create \
  --subscription "az-104" \
  --resource-group "rg-az104-foundation-lab" \
  --storage-account "staz104lab002d36" \
  --name "share1" \
  --quota 5 \
  --access-tier TransactionOptimized \
  --enabled-protocols SMB \
  --output table

12. 把 Azure Files 資料權限限定在 share1，然後使用 Entra ID 上傳檔案

  1. 建立 Azure Files 的 File Share，名稱：share1（上一步）。
  2. 檢查 share1 是否有指派需要的 RBAC Role；此例檢查 Storage File Data Privileged Contributor。
  3. --auth-mode login：使用目前 az login 登入的 Microsoft Entra ID 身分做驗證。

下方 CLI 上傳／下載使用 FileREST；前一步結構圖示範的是 SMB 共用存取。

CLI
USER_ID=$(az ad signed-in-user show \
  --query id \
  --output tsv)

SHARE_SCOPE="/subscriptions/d2ecddbd-2855-485d-8b5e-c7f26b75e3a6/resourceGroups/rg-az104-foundation-lab/providers/Microsoft.Storage/storageAccounts/staz104lab002d36/fileServices/default/fileshares/share1"

az role assignment list \
  --subscription "az-104" \
  --assignee "$USER_ID" \
  --scope "$SHARE_SCOPE" \
  --include-inherited \
  --query "[?roleDefinitionName=='Storage File Data Privileged Contributor'].{
    Role:roleDefinitionName,
    Scope:scope,
    Principal:principalId
  }" \
  --output table

Firewall

14. 建立 firewall, 並封鎖

預設
Storage → Public Endpoint

VNet + Service Endpoint
→ 允許指定 Subnet 存取
→ 搭配 Firewall 才能封鎖其他來源

Private Endpoint
→ 透過 VNet 內的 Private IP 存取 Storage

Service Endpoint 仍使用 Storage 的 Public Endpoint。Private Endpoint 不會自動停用公用存取，需另外設定；本節實作 Service Endpoint + Firewall。官方說明

  1. 建立 VNet、Subnet，並替 Subnet 啟用 Storage Service Endpoint。
  2. 啟動 Storage Firewall：--default-action Deny。
  3. 添加 allowlist：az storage account network-rule add。

下方命令先加入允許清單，再設定 Deny，讓允許來源在切換時已就緒。

建立 vnet

CLI
SUBSCRIPTION_ID="d2ecddbd-2855-485d-8b5e-c7f26b75e3a6"
LAB_RG="rg-az104-foundation-lab"
LAB_LOCATION="eastasia"
STORAGE_ACCOUNT="staz104lab002d36"

VNET_NAME="vnet-az104-storage-lab"
SUBNET_NAME="snet-storage"

az network vnet create \
  --subscription "$SUBSCRIPTION_ID" \
  --resource-group "$LAB_RG" \
  --name "$VNET_NAME" \
  --location "$LAB_LOCATION" \
  --address-prefixes "10.20.0.0/16" \
  --subnet-name "$SUBNET_NAME" \
  --subnet-prefixes "10.20.1.0/24" \
  --tags purpose=az104-learning environment=lab \
  --output none

替 Subnet 啟用 Storage service endpoint

CLI
az network vnet subnet update \
  --subscription "$SUBSCRIPTION_ID" \
  --resource-group "$LAB_RG" \
  --vnet-name "$VNET_NAME" \
  --name "$SUBNET_NAME" \
  --service-endpoints Microsoft.Storage \
  --output none

取得 Subnet ID，加入 Storage firewall 允許清單

CLI
SUBNET_ID=$(az network vnet subnet show \
  --subscription "$SUBSCRIPTION_ID" \
  --resource-group "$LAB_RG" \
  --vnet-name "$VNET_NAME" \
  --name "$SUBNET_NAME" \
  --query id \
  --output tsv)

az storage account network-rule add \
  --subscription "$SUBSCRIPTION_ID" \
  --resource-group "$LAB_RG" \
  --account-name "$STORAGE_ACCOUNT" \
  --subnet "$SUBNET_ID" \
  --output none

設定封鎖

CLI
az storage account update \
  --subscription "d2ecddbd-2855-485d-8b5e-c7f26b75e3a6" \
  --resource-group "rg-az104-foundation-lab" \
  --name "staz104lab002d36" \
  --default-action Deny \
  --output none

Azure Policy

Azure Policy 是把治理規則託管給 Azure，讓 Azure Policy 引擎持續檢查與管理資源是否符合規範

公司不希望每個工程師都自己決定資源怎麼建，可以直接用 Policy 統一限制，例如限制可部署的區域或允許的資源類型。

17. 使用 ARM REST API 建立 Policy Assignment

CLI
az rest \
  --method put \
  --url "https://management.azure.com/subscriptions/d2ecddbd-2855-485d-8b5e-c7f26b75e3a6/resourceGroups/rg-az104-foundation-lab/providers/Microsoft.Authorization/policyAssignments/audit-storage-no-shared-key?api-version=2025-11-01" \
  --headers "Content-Type=application/json" \
  --body '{
    "properties": {
      "displayName": "Audit storage accounts that allow Shared Key",
      "description": "AZ-104 governance lab: audit Storage accounts that allow Shared Key authorization",
      "policyDefinitionId": "/providers/Microsoft.Authorization/policyDefinitions/8c6a50c6-9ffd-4ae7-986f-5fa6111f9a54",
      "parameters": {
        "effect": {
          "value": "Audit"
        }
      },
      "enforcementMode": "Default"
    }
  }' \
  --output none
