01 / Cloud concepts
3 分鐘 · 考綱 25–30%

雲端：按需取得 IT 能力，責任仍要分清楚。

不必先買好整批伺服器，可依需求使用運算、儲存與網路。支出通常從前期設備投資（CapEx）轉向營運支出（OpEx）；實際成本取決於用量、規格與計價方式。

Public 公有雲

供應商提供共用雲端平台，例如 Azure。公有雲不表示你的資料公開。

Private 私有雲

雲端環境供單一組織使用；組織對環境有較高控制與管理責任。

Hybrid 混合雲

連接公有雲與私有環境。例如商店網站在 Azure，部分系統留在公司。
服務模式：你想管理到哪一層？
模式你主要管理直覺例子
IaaS 基礎設施作業系統、應用程式、資料與設定Azure VM：租電腦，自己維護 OS
PaaS 平台應用程式、資料與存取設定；供應商管理 OSApp Service：部署網站程式
SaaS 軟體資料、使用者與可設定的存取控制Microsoft 365：直接使用軟體
共同責任 Shared responsibility：越往 SaaS，供應商負責越多；你仍須對自己的資料、身分與存取負責。Serverless 是不用自行管理底層伺服器，不是沒有伺服器。

擴充 Scalability：垂直＝把一台變大；水平＝增加台數。彈性 Elasticity：隨需求增減資源。高可用性：減少中斷；可靠性：故障後能恢復並持續提供服務。雲端提供能力，仍需要正確設計。

02 / Architecture & services
4 分鐘 · 本節與第 3 節涵蓋 35–40%

先分清「管理層級」與「實際位置」。

Management group跨訂閱套用治理
→ Subscription計費與存取管理範圍
→ Resource group同生命週期資源的容器
→ ResourceVM、儲存帳戶等實體

Region 區域是部署的地理範圍；Availability zone 可用性區域是同一 Region 內，電力、冷卻與網路獨立的資料中心群組。跨 Zone 可降低單一機房故障影響，跨 Region 用於更大範圍災難復原；須視服務能力配置。

Resource group 不是機房，可包含不同 Region 的資源；每個資源只屬於一個 Resource group。Region pair 不代表所有資料自動複寫，也不是每個 Region 都有配對。

商店上線：從需求選服務
需求優先想到選擇理由
需要完整控制 OSVirtual Machines可自訂系統，自己負責維護
直接託管網站 / APIApp Service受管理的應用程式平台
打包程式與相依套件Containers 容器可攜執行環境，共用主機核心
圖片上傳後執行縮圖程式Azure Functions事件觸發的運算
商品圖片、影片、備份物件Blob Storage非結構化物件儲存
需要 SMB / NFS 共用檔案Azure Files受管理的檔案共用
VM 的持久磁碟Azure Managed Disks區塊儲存

網路怎麼連？

VNet / Subnet：私有網路與子網路。
Peering：連接 VNet。
DNS：把名稱解析成 IP。

公司怎麼連雲端？

VPN Gateway：經公用網際網路建立加密通道。
ExpressRoute：私人專用連線，不經公用網際網路；不代表預設端到端加密。

資料如何耐故障？

LRS：單一資料中心。
ZRS：同區域跨 Zone。
GRS / GZRS：加入跨區域複寫；非同步複寫可能有資料落差。
儲存層級：Hot → Cool → Cold → Archive，越少讀取越適合往右選；較低儲存成本通常伴隨較高存取成本或限制。Archive 為離線層級，讀取前需重新水化。複寫不等於備份，誤刪與資料保留仍要另外設計。
多認識幾個考綱名詞（可第二輪再讀）

VM Scale Sets：管理與擴充一組 VM。Availability sets：將 VM 分散至故障／更新網域。Azure Virtual Desktop：遠端桌面與應用程式。Sovereign regions：符合特定政府等需求的隔離雲端環境。

Public endpoint：公開可路由的服務端點，仍需要適當存取控制。Private endpoint：以 VNet 私有 IP 存取支援的服務。

AzCopy：命令列搬檔；Storage Explorer：圖形化管理儲存；File Sync：同步 Windows Server 與 Azure Files；Azure Migrate：評估與移轉工作負載；Data Box：以實體設備搬大量資料。

03 / Identity & governance
3 分鐘

你是誰？能做什麼？資源要遵守什麼？

問題工具 / 概念商店情境
你是誰？Microsoft Entra ID · Authentication員工登入；MFA 增加驗證因素
能做什麼？Azure RBAC · Authorization讓工程師只能讀取指定資源群組
何時准許登入？Conditional Access依使用者、裝置或風險要求 MFA
資源設定合規嗎？Azure Policy限制可部署區域、稽核必要標籤
如何避免誤刪？Resource locksCanNotDelete 防刪；ReadOnly 限制修改
RBAC 管「誰能做」；Policy 管「資源應符合什麼」；Lock 防「意外管理操作」。有權限不代表能繞過 Policy 或 Lock；有權管理鎖的人仍可移除鎖。Lock 主要作用於控制平面，不是資料備份。

Zero Trust 零信任

明確驗證、最小權限、假設已遭入侵。內網也不能無條件信任。

Defense in depth

用身分、網路、主機、應用程式與資料等多層防護，降低單點失守風險。

Defender / Purview

Defender for Cloud：雲端安全態勢與工作負載保護。
Purview：資料治理、探索與合規能力。
SSO、Passwordless、Domain Services 有何差異？

SSO：一次登入存取多個應用程式。Passwordless：用通行金鑰等方式取代密碼。MFA：使用不同類型的驗證因素。External identities：讓外部夥伴等使用者協作。Entra Domain Services：提供受管理的網域加入、LDAP、Kerberos 等傳統網域能力；Entra ID 本身不等同傳統 AD DS。

2 分鐘 · 治理與管理共 30–35%

Pricing calculator 依區域、規格、數量與用量估算。實際帳單還會受資料傳輸與購買方案等影響。

運作中：控成本

Cost Management 分析費用、設定預算與通知。Tags 用鍵值標記部門／專案，協助分類。

需求穩定：選方案

隨用隨付較彈性；Reservations / savings plans 以適用承諾換折扣。Spot 較便宜但可能被收回，適合可中斷工作。
預算通知不會自動停止所有資源。VM 停止（仍配置）與解除配置不同；解除配置後，磁碟等仍可能計費。
你想知道工具一句話記憶

管理入口：Portal 是網頁介面；CLI / PowerShell 是命令工具；Cloud Shell 是瀏覽器中的命令環境。ARM 是 Azure 資源管理層；ARM templates / IaC 用宣告式定義重現部署。Azure Arc 把管理能力延伸到地端與其他雲端資源。
