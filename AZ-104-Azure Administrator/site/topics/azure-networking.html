Azure Networking

VNet、流量控管與 Load Balancer 實作筆記

Internet → Public IP → Load Balancer → NIC → VM
                                      │
                                      └→ Subnet → VNet
建置
Resource Group → VNet / Subnets → 雙向 Peering
控管
NSG / ASG → UDR → Storage Service Endpoint
部署
Quota gate → Public IP → Load Balancer → NIC → VM
驗收
nginx → 驗收紀錄

心得總結

  1. 外部流量進入 VM
    Internet → Load Balancer 的 Public IP → 後端 NIC 私有 IP → VM。
  2. 網路分區、互連與放行
    使用 VNet / Subnet 分區，透過 Peering 互連不同 VNet，並設定 NSG 規則控制流量放行。
  3. 指定流量先經過 Firewall
    設定 UDR，把符合目的網段的流量導向 Firewall 的私有 IP，再由 Firewall 檢查與放行。
  4. 限制 PaaS 服務接受哪些 Subnet 的連線
    在來源 Subnet 啟用 Service Endpoint，讓支援的服務辨識來源網路，並搭配服務端的網路規則限制允許的 Subnet。

2. VNet 與 subnets

Hub-and-spoke 是一種網路架構。

如果各個後端分別管理對外連線，就需要各自設定哪些 Domain、Port、IP 可以通，也要各自記錄連線。採用 Hub 並將流量導向其中的 Firewall 後，就可以集中設定規則與記錄連線。

VNet A 10.16.0.0/16  ✕  VNet B 10.17.0.0/16
VNet A  ← Peering →  VNet B
Azure Network
│
├─ VNet: vnet-issue16-hub        10.16.0.0/16
│  │
│  ├─ Subnet: snet-web           10.16.1.0/24
│  │    └─ NIC
│  │        └─ Web VM
│  │
│  └─ Subnet: snet-app           10.16.2.0/24
│       └─ App / Backend
│
│          VNet Peering
│               │
│               ▼
└─ VNet: vnet-issue16-spoke      10.17.0.0/16
   │
   └─ Subnet: snet-workload      10.17.1.0/24
        └─ Workload

2.1 Hub VNet 與 Web subnet

az network vnet create 的回傳結構不保證包含可用的 newSubnet 查詢結果，因此建立與驗證分開執行。

Bash · Azure CLI
az network vnet create \
  --resource-group "$AZ104_RG" \
  --location "$AZ104_LOCATION" \
  --name "vnet-issue16-hub" \
  --address-prefixes "10.16.0.0/16" \
  --subnet-name "snet-web" \
  --subnet-prefixes "10.16.1.0/24" \
  --output none

az network vnet subnet list \
  --resource-group "$AZ104_RG" \
  --vnet-name "vnet-issue16-hub" \
  --query '[].{name:name,prefix:addressPrefix,state:provisioningState}' \
  --output table

本次建立輸出中的 subnet 欄位曾顯示 null，但後續唯讀查詢確認 snet-web 已成功建立；不能只用單一 CLI 回傳欄位判定資源不存在。

3. 雙向 VNet peering

先取得兩個 VNet 的 resource ID，不把完整 ID 寫入文件：

Bash · Azure CLI
export AZ104_HUB_ID="$(
  az network vnet show \
    --resource-group "$AZ104_RG" \
    --name "vnet-issue16-hub" \
    --query id \
    --output tsv
)"

export AZ104_SPOKE_ID="$(
  az network vnet show \
    --resource-group "$AZ104_RG" \
    --name "vnet-issue16-spoke" \
    --query id \
    --output tsv
)"

建立 Hub 到 Spoke。只有一個方向時，本次觀察到狀態為 Initiated：

Bash · Azure CLI
az network vnet peering create \
  --resource-group "$AZ104_RG" \
  --vnet-name "vnet-issue16-hub" \
  --name "peer-hub-to-spoke" \
  --remote-vnet "$AZ104_SPOKE_ID" \
  --allow-vnet-access \
  --query '{name:name,state:peeringState,access:allowVirtualNetworkAccess}' \
  --output table

建立反方向：

Bash · Azure CLI
az network vnet peering create \
  --resource-group "$AZ104_RG" \
  --vnet-name "vnet-issue16-spoke" \
  --name "peer-spoke-to-hub" \
  --remote-vnet "$AZ104_HUB_ID" \
  --allow-vnet-access \
  --query '{name:name,state:peeringState,access:allowVirtualNetworkAccess}' \
  --output table

兩端都必須驗證為 Connected：

Bash · Azure CLI
az network vnet peering list \
  --resource-group "$AZ104_RG" \
  --vnet-name "vnet-issue16-hub" \
  --query '[].{vnet:`hub`,name:name,state:peeringState}' \
  --output table

az network vnet peering list \
  --resource-group "$AZ104_RG" \
  --vnet-name "vnet-issue16-spoke" \
  --query '[].{vnet:`spoke`,name:name,state:peeringState}' \
  --output table

控制平面的 Connected 不等於工作負載流量已驗證；本次沒有 VM runtime 證據。

4. NSG 與 ASG

  1. 先分區 → VNet / Subnet
    例如：訂單、付款、會員 → 拆成不同 VNet / Subnet。
  2. 再接通 → Peering
    例如：訂單 VNet 要連付款 VNet → 建立 Peering。
  3. 決定流量走哪裡 → Route Table
    例如：所有後端連 Internet → 先導到 Hub Firewall。
  4. 決定哪些流量可以通 → NSG
    例如：Internet → Web VM → 只允許 TCP 80 / 443。
  5. VM 太多先分組 → ASG
    例如：web01、web02、web03 → 將它們的 NIC 加入 asg-web，再讓 NSG 對 asg-web 設規則。
  6. 統一管理網路規則 → Firewall
    例如：訂單、付款、會員的 Internet 流量 → 都經過 Hub Firewall，統一管理 Domain、Port、IP 與連線 Log。
Bash · Azure CLI
az network asg create \
  --resource-group "$AZ104_RG" \
  --location "$AZ104_LOCATION" \
  --name "asg-web" \
  --tags purpose=az104-learning issue=16 \
  --query '{name:name,location:location,state:provisioningState}' \
  --output table

az network nsg create \
  --resource-group "$AZ104_RG" \
  --location "$AZ104_LOCATION" \
  --name "nsg-web" \
  --tags purpose=az104-learning issue=16 \
  --query '{name:NewNSG.name,state:NewNSG.provisioningState}' \
  --output table

az network nsg rule create \
  --resource-group "$AZ104_RG" \
  --nsg-name "nsg-web" \
  --name "Allow-HTTP-To-ASG" \
  --priority 100 \
  --direction Inbound \
  --access Allow \
  --protocol Tcp \
  --source-address-prefixes Internet \
  --source-port-ranges "*" \
  --destination-asgs "asg-web" \
  --destination-port-ranges 80 \
  --description "Allow HTTP only to web ASG members" \
  --query '{name:name,priority:priority,access:access,protocol:protocol,destinationAsgCount:length(destinationApplicationSecurityGroups),destinationPort:destinationPortRange,state:provisioningState}' \
  --output table

NSG 自訂規則 priority 的有效範圍從 100 開始；本次嘗試 90 時 Azure 正確拒絕。

將 NSG 關聯到 snet-web：

Bash · Azure CLI
az network vnet subnet update \
  --resource-group "$AZ104_RG" \
  --vnet-name "vnet-issue16-hub" \
  --name "snet-web" \
  --network-security-group "nsg-web" \
  --query '{subnet:name,prefix:addressPrefix,nsgAttached:contains(networkSecurityGroup.id, `nsg-web`),state:provisioningState}' \
  --output table

5. User-defined route

UDR（User-defined route）是自訂路由，用來決定 Subnet 的流量要送去哪裡。

在典型 Hub-and-Spoke 架構裡，通常靠 UDR 把 Spoke 的流量導到 Hub Firewall；如果沒有 UDR，流量不會因為有 Hub 就自動先經過 Hub Firewall。

Spoke → UDR → Hub Firewall → Internet

以下練習設定 snet-app → 10.99.0.0/16 → None，將前往該網段的流量丟棄。

Bash · Azure CLI
az network route-table create \
  --resource-group "$AZ104_RG" \
  --location "$AZ104_LOCATION" \
  --name "rt-app" \
  --disable-bgp-route-propagation false \
  --tags purpose=az104-learning issue=16 \
  --query '{name:name,bgpPropagationDisabled:disableBgpRoutePropagation,state:provisioningState}' \
  --output table

az network route-table route create \
  --resource-group "$AZ104_RG" \
  --route-table-name "rt-app" \
  --name "Block-Test-Network" \
  --address-prefix "10.99.0.0/16" \
  --next-hop-type None \
  --query '{name:name,prefix:addressPrefix,nextHop:nextHopType,state:provisioningState}' \
  --output table

az network vnet subnet update \
  --resource-group "$AZ104_RG" \
  --vnet-name "vnet-issue16-hub" \
  --name "snet-app" \
  --route-table "rt-app" \
  --query '{subnet:name,prefix:addressPrefix,routeTableAttached:contains(routeTable.id, `rt-app`),state:provisioningState}' \
  --output table

6. Storage service endpoint

Service Endpoint 讓支援的 Azure PaaS 服務認得來源 Subnet，並可搭配服務端的網路存取規則，限制哪些 Subnet 可以連線。

Subnet → Service Endpoint → Azure Storage / Azure SQL / ACR

不是所有 Azure 服務都支援 Service Endpoint；各服務的支援範圍與限制，請參考 Microsoft 官方文件。

Bash · Azure CLI
az network vnet subnet update \
  --resource-group "$AZ104_RG" \
  --vnet-name "vnet-issue16-hub" \
  --name "snet-app" \
  --service-endpoints Microsoft.Storage \
  --query '{subnet:name,serviceEndpoints:serviceEndpoints[].service,state:provisioningState}' \
  --output json

這只證明 subnet 已啟用 Microsoft.Storage service endpoint。它不會自動修改 Storage Account firewall，也不等於 Private Endpoint。

7. Compute quota gate

所有會計費的 VM、Public IP 與 Load Balancer 資源，都必須在 quota gate 通過後才建立。

VM 規格有提供，但你的訂用帳戶在 East Asia 的 Basv2 配額是 0，所以無法建立 VM。 處理過程：

  1. 註冊 Microsoft.Quota：讓 Azure 可以查詢及申請配額。
  2. 註冊 Microsoft.Compute：讓訂用帳戶可以使用及顯示 VM 配額。
  3. 在 Portal 找到：
    • Standard Basv2 Family vCPUs
    • Region：East Asia
    • 目前配額：0
  4. 申請新配額：2。 申請及持有配額不收費；只有成功建立 VM 後才開始產生 VM 費用。
Bash · Azure CLI
export AZ104_VM_SIZE="Standard_B2ats_v2"

az vm list-skus \
  --location "$AZ104_LOCATION" \
  --resource-type virtualMachines \
  --size "$AZ104_VM_SIZE" \
  --all \
  --query "[?name=='$AZ104_VM_SIZE'].{name:name,restrictionReasons:restrictions[].reasonCode}" \
  --output json

az vm list-usage \
  --location "$AZ104_LOCATION" \
  --query "[?name.value=='standardBasv2Family'].{name:name.localizedValue,current:currentValue,limit:limit}" \
  --output table

8.3 Health probe、inbound rule 與 outbound rule

Bash · Azure CLI
az network lb probe create \
  --resource-group "$AZ104_RG" \
  --lb-name "lb-issue16-web" \
  --name "hp-http" \
  --protocol Http \
  --port 80 \
  --path "/" \
  --interval 5 \
  --threshold 2 \
  --query '{name:name,protocol:protocol,port:port,path:requestPath,interval:intervalInSeconds,threshold:numberOfProbes,state:provisioningState}' \
  --output table

az network lb rule create \
  --resource-group "$AZ104_RG" \
  --lb-name "lb-issue16-web" \
  --name "rule-http" \
  --protocol Tcp \
  --frontend-ip-name "fe-public" \
  --frontend-port 80 \
  --backend-pool-name "be-web" \
  --backend-port 80 \
  --probe-name "hp-http" \
  --idle-timeout 4 \
  --enable-tcp-reset true \
  --disable-outbound-snat true \
  --query '{name:name,protocol:protocol,frontendPort:frontendPort,backendPort:backendPort,probeConfigured:contains(probe.id, `hp-http`),outboundSnatDisabled:disableOutboundSnat,state:provisioningState}' \
  --output table

az network lb outbound-rule create \
  --resource-group "$AZ104_RG" \
  --lb-name "lb-issue16-web" \
  --name "outbound-web" \
  --protocol All \
  --frontend-ip-configs "fe-public" \
  --address-pool "be-web" \
  --outbound-ports 1024 \
  --idle-timeout 4 \
  --query '{name:name,protocol:protocol,ports:allocatedOutboundPorts,frontendConfigured:contains(frontendIPConfigurations[0].id, `fe-public`),backendConfigured:contains(backendAddressPool.id, `be-web`),state:provisioningState}' \
  --output table

本次 ARM preflight 回傳 QuotaExceeded：East Asia 的 standardBasv2Family limit 為 0，部署需要 2 cores。Preflight 失敗後用下列命令確認沒有留下 VM 或 managed disk：

結果沒有任何資料列。Azure CLI 額外顯示的 The content for this response was already consumed 是處理原始 ARM 錯誤時的次要例外，不是根因。
